Схема `searches`: `id` PK, `user_id` FK `users.id`/unique, непустые `rooms` (ARRAY smallint) и `conditions` (ARRAY varchar(32)), `price_low <= price_high`, `baseline_at`, `confirmed_at`, `created_at`, `updated_at`. Схема `search_drafts`: `user_id` PK/FK, `mode` (`create`/`edit`), `step` (`rooms`/`condition`/`price`/`summary`/`edit_menu`), массивы выбора, nullable пара `price_low`/`price_high` (оба `None` до выбора), `reached_summary`, `updated_at`. `test_models_match_migrations` должен остаться зелёным.

Писатель draft — сервис через обработчики кликов; выход из create-draft — подтверждение, из edit-draft — подтверждение либо «⬅️ Назад» с удалением, при брошенном редактировании запись остаётся для продолжения и не влияет на `Search`. Писатель `Search`/`baseline_at` — только `confirm_draft`; новые параметры и baseline видны вместе после commit, при исключении откатываются. Писатель `subscription_state=active` здесь — первое подтверждение; ручную паузу владеющий ею сценарий этапа 10 снимает только по своему явному действию, этап 5 её не сбрасывает. `processed_updates` middleware этапа 3 хранит повтор Telegram `update_id` в той же DB-транзакции. Целевые значения callback и блокировка draft защищают от повторного клика; устаревшая клавиатура не должна менять другой шаг, после подтверждения отсутствующий draft не создаёт повторного результата.

Стыковка этапов 3–4: `User`, `SubscriptionState`, `str_enum`, middleware-данные `session`/`db_user`/`clock`, `build_dispatcher` и `tests.tg` уже существуют; `SearchCriteria`, `RoomOption`, `ConditionGroup`, `PRICE_SEGMENTS`, `PriceRange`, `click_price` и `catalog.matching.count_matching` берутся **без изменения их контрактов**. `count_matching` фильтрует `ObjectState.eligible=True`, комнаты, состояние и `price_segment`; Airtable напрямую для счётчика не опрашивается. `VIEW_RESULTS` и выдача карточек — этап 6; до него callback обрабатывает fallback пустым `answerCallbackQuery`. «Мій пошук», «Збережені ❤️», «Допомога», «🏠 Продати квартиру» пока ведут в предусмотренный планом fallback до соответствующих этапов.
